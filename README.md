# ai-assist

The AI harness for the bank-harness solution. Its main job, in two steps:

1. **Refine requirements** — turn a rough ask into a checked, business-language requirement.
2. **Turn that requirement into a spec** — with acceptance criteria written in BDD style
   (Given/When/Then, concrete example data), ready for implementation planning.

It also **runs the solution as a whole** — the only place that knows about all the moving parts.

This is the one repository that works **across** the others. The rest are deliberately
self-contained.

## Refining a requirement

```bash
/refine R-001-daily-withdrawal-limit
```

Run bare to pick from a list, or with a slug to go straight there. Sessions are resumable and
versioned — pause any time, resume anywhere, re-refine into a v2 that carries forward everything
unresolved.

| | Job |
|---|---|
| [`/refine`](.claude/commands/refine.md) | Entry point — resolves the folder, decides new / resume / re-refine |
| [`refine-requirement`](.claude/skills/refine-requirement/SKILL.md) | The session — context, records, state, versioning |
| [`interview-me`](.claude/skills/interview-me/SKILL.md) | The questioning method |

Most of this needs no codebase. The knowledge base is written to be read on its own.

## Creating a spec, with BDD acceptance criteria

Once a requirement is refined (`requirements-v<n>.md` exists), feed it straight in — no
copy-paste:

```bash
/specify-requirement create-account-upgrade
```

This produces `specs/<NNN>-<name>/spec.md`: User Stories, Acceptance Scenarios, and Functional
Requirements, **every one written as Given/When/Then with concrete example data** — not
"given an invalid input", but "given a credit account with a $500 limit and a $0 balance, when
a $600 withdrawal is requested, then refused with 'Insufficient funds'". That shape is
enforced by [the constitution](.specify/memory/constitution.md), not left to whoever writes the
spec that day.

| | Job |
|---|---|
| [`/specify-requirement`](.claude/commands/specify-requirement.md) | Entry point — resolves the requirement, guards against feeding it in twice, hands it to `speckit-specify` |
| `speckit-specify` (and the rest of the `speckit-*` skills, installed by [spec-kit](https://github.com/github/spec-kit)) | Produces the spec, then (optionally) the implementation plan, tasks, and code |
| [`.specify/memory/constitution.md`](.specify/memory/constitution.md) | Governs the BDD acceptance-criteria style — amend it, don't drift from it spec-by-spec |

Full pipeline diagram, what lives in each `specs/<NNN>-<name>/` folder, and where this harness's
role ends (it has no codebase of its own to plan or build against): see
**[`specs/README.md`](specs/README.md)**.

## Layout

```
ai-assist/
  harness.config.json    what this harness is connected to — read this first
  CLAUDE.md              working instructions for AI assistants
  requirements/          one file per requirement — step 1 output
  specs/                 one folder per spec, BDD acceptance criteria — step 2 output
  .specify/              spec-kit's own config, templates, and constitution
  templates/             the requirement template
```

## What it's connected to

Declared in [`harness.config.json`](harness.config.json), with relative paths:

| | Role | Access |
|---|---|---|
| `../bank-harness-kb` | Canonical business knowledge — vocabulary, rules, journeys, constraints | read-write |
| `../bank-harness` | Banking service — owns accounts, transactions, and all money rules | **read-only** |
| `../bank-harness-fe` | Customer application — presents accounts, decides nothing about money | **read-only** |

The two implementation repos are read-only from here, and their `CLAUDE.md` and `docs/` are
generated by tooling — **never hand-edit them**. New business knowledge belongs in the knowledge
base.

## Running the solution

See the `runtime` section of the config. Start the datastore first — the service exits
immediately if it can't reach one. There is no seed data, so create and fund an account before
expecting withdrawals or transfers to do anything.
